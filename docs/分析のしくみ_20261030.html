クウハクスコープ 分析のしくみ

10種類の分析が、それぞれ何をどう計算しているか

2026-10-30（10-12版を改訂） ／ 公開アプリ: https://transit-accessibility-aik9qbme9ej2ue8wamnpvf.streamlit.app ／ 数値の例は室蘭市・道南バス（2026年10月1日改正ダイヤ）の平日

この資料の読み方：10種類の分析は、ばらばらの仕組みではありません。すべて「時刻表をもとに、何時にどこへ着けるかを調べる」1つの計算の上に乗っています。まず第1章でその共通の計算を説明し、第2〜4章で各分析がそれをどう使っているかを説明します。専門用語は、初めて出てきたところで説明します。

1. すべての分析の土台

1.1 時刻表を「路線のつながり」に変える

バスの時刻表は、国が定めた共通形式（GTFS-JP）でオープンデータとして公開されています。アプリはこれを読み込み、次の2種類の「つながり」に変換します。

  • バスの区間：「〇〇便は、Aを8:20に出てBに8:24に着く」という、便1本・区間1つごとの記録。平日だけで32,536区間あります。「AとBはつながっている」ではなく「Aを8:20に出る便がある」という形で持つのがポイントです
  • 徒歩の乗り換え：300m以内にある停留所どうしは歩いて乗り換えられるものとします（分速67m＝一般的な歩行速度）

1.2 何時にどこへ着けるかを計算する（時刻依存ダイクストラ法）

乗換案内アプリと同じことを、すべての停留所について一度に行います。乗換案内が「A駅からB駅まで」を1つ答えるのに対し、このアプリは「A停留所を8:00に出たら、市内のすべての停留所にそれぞれ何時に着けるか」を答えます。

普通の最短経路の計算（ダイクストラ法）は「距離が短い順」に道をたどります。バスの場合は、何時に停留所に着いたかで、次に乗れる便が変わります。8:15に着けば8:20発に乗れますが、8:25に着くと次は9:00発まで待つことになります。そこで「到着時刻が早い順」に停留所を確定していく形に変えたものが時刻依存ダイクストラ法です。

決まりごと：歩いて乗り換えたあとに、さらに歩いて乗り換えることはできません（これを許すと、300mの徒歩をつないで市内を歩くだけで横断できてしまうため）。急行が各駅停車を追い越す場合も、便を1本ずつ調べているので早く着く方が選ばれます。

1.3 逆向きに計算する（逆方向探索）

1.2 は「ここを何時に出たら、どこに何時に着けるか」です。これを逆にすると「ここに何時までに着くには、どこを何時までに出ればよいか」がわかります。手順は同じで、時刻表を後ろからたどり、「出発時刻が遅い順」に確定していきます。

逆方向の利点は計算量です。「市内のすべての場所から病院へ行けるか」を順方向で調べると、場所の数だけ計算が要ります。逆方向なら病院から1回たどるだけで、すべての場所について答えが出ます。時間空白診断で、3,079か所×216通りの到着時刻（5〜22時台を5分刻み）の判定が1秒ほどで終わるのはこのためです。

1.4 人口とつなぐ

人口は簡易100mメッシュ人口を使います。地図を100m四方のマスに区切り、令和2年国勢調査の250mメッシュ人口を、マスの中の建物面積に応じて按分した推計値です（作成：西澤明、東京大学空間情報科学研究センター、CC BY）。1マスごとの値は実際の人数そのものではないため、広い範囲で合計して使います。室蘭市は3,079マス、83,050人です。停留所と人口の結びつけ方は、分析によって2通りあります。

方式考え方使う分析
停留所の周り300m計算でたどり着けた停留所から半径300m以内のマスの人口を数える（重複は1回だけ）路線廃止・減便・バス停削除・代替路線追加・集客圏分析
住まいから歩いて500mマスの中心から歩いて行ける停留所（既定500m）を探し、そこまでの徒歩時間も含めて間に合うかを判定する時間空白診断・改善策

後者のほうが「住んでいる人が実際にバス停まで歩く」ことまで計算に入るので、空白の判定には後者を使っています。前者は以前からある分析で使っている方式です。

1.5 平日・土曜・日祝の切り替え

時刻表には曜日ごとの運行パターンが書かれています。サイドメニューの「ダイヤ」を切り替えると、その曜日に走る便（平日808便・土曜672便・日祝667便）だけを使って、すべての分析を計算し直します。

1.6 時刻は5分刻みで動かし、時間帯ごとに平均する

同じ場所でも、到着時刻が数分違うだけで、間に合う便があるかが変わります。例えば休日に東室蘭駅東口へ着きたいとき、間に合わない人は7:00着なら市の46.1%、7:35着なら11.9%です。そこで、時刻を毎時00分の1点だけで測るのをやめ、5分刻み（1日216通り）で計算し、時間帯（例：7時台＝7:00〜7:55着の12通り）ごとに平均します。休日7時台の平均は27.9%です。画面と資料では、平均とあわせて時間帯の中の幅（最小〜最大）も示します。

以前の版は毎時00分の1点で測っていました。「休日7時に46.1%」は7時台で最も悪い1分の値で、「5時台と10時台で到達できる停留所が27.6倍違う」は始発前の5:00発を5時台の代表にした値でした（5分刻みの平均では約7倍）。

2. ① 空白を見つける

今の時刻表のままで、どこに・いつ・何人が困っているかを調べる分析です。時刻表は変えません。

時間空白診断（3D）

わかること
生活拠点（例：東室蘭駅東口）に、指定の時間帯に着けない人がどこに何人いるか。このアプリの中心となる分析です
設定
生活拠点のバス停、制限時間（既定60分）、バス停まで歩ける距離（既定500m）、歩く速さ（一般／高齢者）
しくみ
  1. 生活拠点から逆方向にたどり、すべての停留所について「何時までに出れば間に合うか」を求める
  2. 人口のマスごとに、歩いて行ける停留所の中で一番遅く出られるものを選び、そこまでの徒歩時間を引く
  3. それが「到着時刻 − 制限時間」より前なら間に合わない＝空白と判定する。つまり到着時刻の60分前以降に家を出て間に合うかを見ており、早く着いて拠点で待つ時間も60分に含む（始発で6時に着いて9時まで待つ人を「9時に着ける」と数えると、時間空白が見えなくなるため）。そのため到着時刻を遅らせても空白が減るとは限らない（休日 7:45着17.5% → 8:00着27.5%）
  4. これを到着時刻5:00〜22:55の5分刻み（216通り）で行い、時間帯ごとに平均する（1.6参照）。マスごとに「1日のうち何時間着けないか」も数える
空白の種類
静的空白：歩ける範囲にバス停が1つもない（時刻に関係なく着けない）。
時間空白：バス停はあるのに、時刻表の都合で間に合わない。このアプリが測りたいのはこちらです
地図の見方
500m四方ごとの柱。高さ＝その時間帯に着けない人数（平均）、灰色＝静的空白、暖色＝時間空白（色が濃いほど1日のうち着けない時間が長い）、青い点＝生活拠点。到着時刻ごとの空白人口を5分刻みの折れ線でも示す

時間帯別到達圏

わかること
同じ停留所から出発しても、時間帯によって行ける範囲がどれだけ変わるか
設定
出発バス停、制限時間
しくみ
出発時刻を5:00〜22:55の5分刻みで変えながら、順方向の計算を216回行う。時間帯ごとに、各停留所へ何通りの出発時刻から行けるかを数える。行ける停留所の数を5分刻みの折れ線にする
地図の見方
その時間帯ならいつ出ても行ける 半分以上の出発時刻で行ける 出発時刻しだい。例：室蘭駅前から60分以内に行ける停留所は、5時台の出発で平均35か所（出発時刻により10〜93）、10時台で平均238か所（132〜329）で、約7倍の差

到達圏のみ

わかること
ある停留所をある時刻に出たとき、制限時間内にどこまで行けるかと、それぞれの乗り継ぎ経路
設定
出発バス停、出発時刻、制限時間
しくみ
順方向の計算を1回行う。各停留所に「どの便で来たか」も記録しておき、そこから逆にたどって経路を復元する
地図の見方
所要時間で色分け：15分以内 30分以内 45分以内 それ以上。停留所をタップすると乗り継ぎ経路が出る

集客圏分析

わかること
ある施設（病院・学校など）に指定の時刻までに着くには、どこから来られるか。施設側から見た「お客さんが来られる範囲」です
設定
施設の種類と施設名、到着時刻、制限時間
しくみ
  1. 施設から500m以内で一番近いバス停を探す（なければ分析できない）
  2. そのバス停から逆方向にたどり、各停留所の「何時までに出れば間に合うか」を求める
  3. たどり着けた停留所の周り300mに住む人口を数える
地図の見方
所要時間で色分け（15分・30分・45分で区切り）。停留所をタップすると、そこを何時までに出れば間に合うかが出る

施設アクセス

わかること
ある停留所から出発して、制限時間内にどの施設へ行けるか（国土数値情報の医療機関・学校など142件）
設定
出発バス停、出発時刻、制限時間、施設の種類、歩く速さ
しくみ
  1. 出発停留所から順方向の計算を1回行う
  2. 各施設について、500m以内にあるすべてのバス停で「バスで着ける時刻＋そこから施設まで歩く時間（選んだ歩く速さで計算）」を求め、最も早いものを施設までの所要時間とする
  3. 所要時間が制限時間以内なら「行ける」とする（歩く時間も制限時間に含む）
地図の見方
行ける施設と行けない施設を一覧と地図で表示する。500m以内にバス停がない施設は対象外

3. ② 廃止・減便シミュレーション

時刻表を仮に書き換えて、その前後で行ける範囲を比べる分析です。3つとも同じ流れで動きます。

共通の流れ：① 今の時刻表で順方向の計算をする → ② 時刻表から便や停留所を取り除いた「仮の時刻表」を作る → ③ 仮の時刻表で同じ計算をする → ④ 停留所ごとに前後を比べる

到達不能：前は行けたのに行けなくなった ／ 悪化：行けるが、所要時間が指定の分数（悪化閾値、既定1分）以上延びた ／ 影響なし

あわせて、行けなくなった停留所の周り300mに住み、ほかに行ける停留所もない人を「影響を受ける人口」として数えます（近くに別の停留所があれば、その人は影響なしと数えます）。

路線廃止

わかること
ある路線がなくなったら、どこに行けなくなるか
設定
廃止する路線（複数同時も可）。出発バス停から直接乗れる路線と、乗り換えで使っている路線に分けて表示する。高速バスは市内交通と性質が違うため選択肢から外している
仮の時刻表
選んだ路線の便をすべて取り除く

減便

わかること
便を減らしたら、行ける範囲や所要時間がどう変わるか
仮の時刻表
3つの方式から選ぶ。どれも便を方向・経路（停留所の並び）ごとに出発時刻順に並べて間引くので、片方向だけが全廃になることはない。
・半分にする：選んだ路線の便を、方向・経路ごとに1本おきに残す（1本目・3本目…）
・N本に1本残す：選んだ路線の便を、方向・経路ごとにN本ごとに1本だけ残す（Nは2〜6）
・全路線一律：すべての路線で、方向・経路ごとに指定の割合（10〜80%）前後の本数を、1日の中で偏らないよう取り除く。割合を上げると取り除く便が増えるだけで、前の割合で取り除いた便は戻らない。実際に減った便数と割合を表示する（指定との差は1ポイント程度）

バス停削除

わかること
あるバス停を廃止したら、どこに影響が出るか
仮の時刻表
路線は残し、削除したバス停を通過する扱いにする（前後の停留所を直接つなぐ）。そのバス停を使った徒歩乗り換えも取り除き、近くの停留所どうしを歩いてつなぎ直す。徒歩の範囲は300m（都市部の基準）か500m（地方部の基準）から選ぶ

4. ③ 改善策の比較

空白を減らすために時刻表をどう変えればよいかを試す分析です。

改善策

わかること
増便やダイヤの組み替えで、空白人口が何人減るかと、そのためにどれだけ費用がかかるかを、複数の案で比べる
設定
生活拠点と、対象とする時間帯（例：休日の7時台）。足す便が拠点を通る時間帯（既定は対象の時間帯）・便数、ダイヤシフトで便を減らす時間帯・便数
しくみ
  1. 時間空白診断と同じ方法で、対象の時間帯の空白を求める（5分刻みの平均）
  2. 候補の路線を選ぶ：その時間帯に一度でも空白になる場所の近くの停留所を、多く通る路線から順に並べる。便数の多い路線を選んでも空白は減らない（例：室蘭で最も便の多い路線は129停留所を通るが、空白の場所は1つも通らない）
  3. 候補路線ごとに2種類の案を作る。増便：拠点を通る時刻が指定の時間帯に入るよう、上りと下りそれぞれ便を等間隔に足す（拠点を通らない系統は始発時刻で置く）。ダイヤシフト：便の総数は変えずに、空いている時間帯から困っている時間帯へ便を移す
  4. それぞれの案で、5〜22時台の到着時刻（5分刻み）すべてについて空白人口を計算し直し、今との差を時間で積み上げる（単位は人・時間。100人が1時間着けなかった状態を解消すると100人・時間）
  5. 費用の目安として運行キロ（足した便の数×路線の長さ）の増え方を出し、「空白を1人・時間減らすのに何km走らせる必要があるか」を並べる
大事な点
ダイヤシフトは、狙った時刻だけを見ると必ず良くなります。しかし便を抜いた時間帯は悪くなります。そのため1日全体で評価しています。1日全体では悪化する案は、注意として表示します
出てくるもの
比較表と、それをもとにした自治体向けの政策文書の下書き。数値と推奨はすべて計算で決まり、生成AIは使いません（希望すれば、自分のAPIキーで文章だけを整えられます）

代替路線追加

わかること
ある路線を廃止して、代わりに新しい路線を走らせたら、行ける範囲がどう変わるか
設定
廃止する路線（なしも可）、新しい路線が通るバス停（2〜8か所、順番どおり）、運行間隔、平均速度
仮の時刻表
5時〜22時に、指定の間隔で、行き・帰りの両方向とも始発から新しい便を作る。停留所間の所要時間は、直線距離÷平均速度に、停車時間30秒を足したもの。あとは「② 廃止・減便」と同じように前後を比べる

6. 10-12版からの修正

10-12版で「まだ修正していない」と書いた2件を含め、次の点を直しました。

分析以前の動き修正後
すべての時間帯の値毎時00分の1点だけで測っていた。数分の違いで結果が大きく変わり、00分がたまたま最悪・最良の時刻だと時間帯の値を取り違えた5分刻みで計算し、時間帯の平均と幅を示す（1.6）
代替路線追加帰り方向の便に行きと同じ時刻を割り当て、帰りは区間ごとに次の便を待つ計算になっていた（行き20分・帰り95分）帰り方向も始発から時刻を積み上げて作る（行きと帰りの所要時間が同じになる）
施設アクセス「高齢者（分速40m）」を選んでも徒歩時間は分速67mで、制限時間とも比べず、最寄りの1停留所しか見ていなかった選んだ速さで歩く時間を含めて制限時間と比べ、500m以内の停留所から最も早く着けるものを使う
減便方向を区別せず間引くため、2方向以上ある路線の約3分の1で片方向が全廃・全存続になっていた。「N本に1本」はNを選べず、一律削減は実際の削減率が指定とずれていた（平日50%指定で実際は46%）方向・経路ごとに間引く。Nを選べる。実際の削減率は指定の±1ポイント程度で、画面に表示する
改善策足す便を始発時刻で置いていたため、既定の「5〜9時に1便」が7:00発になり、7時台に拠点へ着く便にならなかった拠点を通る時刻で置く。既定の時間帯は対象の時間帯に合わせる

7. 前提と限界

  • 家からバス停までは直線距離で歩くとみなす。実際の道のりを直線の1.3倍とすると、休日7:00着の空白は46.1%から53.8%に、静的空白は3,793人から7,613人に増える
  • 乗り換えの余裕時間は見込まない（時刻表上で間に合えば乗り継げる）。遅延・混雑も考えない
  • 鉄道・自家用車・タクシーは含めない。バスのみで行けるかを見る
  • 出発地の停留所名に複数の乗り場（ポール）がある場合、到達圏系の分析は先頭の乗り場から計算する（空白診断の生活拠点はすべての乗り場を使う）
